# سرا — سایت رزرو هتل (Next.js + Tailwind، بدون TypeScript)

```bash
npm install
npm run dev     # http://localhost:3000
```

## صفحه‌ها
| آدرس | توضیح |
|---|---|
| `/` | صفحه اول: جستجو با نام شهر، مقصدها، هتل‌ها، مقاله‌ها، سؤالات متداول |
| `/hotels` و `/city/<slug>` | همه‌ی هتل‌ها یا یک شهر، با تغییر شهر و فیلتر قیمت/ستاره/امتیاز/امکانات |
| `/checkout?hotel=<id>` | پرداخت: اتاق، تاریخ، تعداد، امکانات اضافی، کد تخفیف `SARA20`، اطلاعات مهمان |
| `/bookings` | رزروهای حساب من (آینده، گذشته، لغو/باطل شده) — از مونگو |
| `/track` | پیگیری رزرو با کد پیگیری (`/track?code=SR-XXXXXX`)؛ بدون نیاز به ورود |
| `/compare` | مقایسه تا ۳ هتل |
| `/favorites` | هتل‌های قلب‌خورده |
| `/assistant` | دستیار سفر (هوش مصنوعی یا تحلیل ساده) |
| `/blog`, `/blog/<slug>` | وبلاگ |
| `/contact` | ارتباط با ما |
| `/login` | ورود و ثبت‌نام (نمایشی) |

## داده و تنظیمات
- ۱۱۰ هتل فرضی: `data/hotels.js` (تصویر نمونه‌ی هر هتل در `public/hotels/<id>.svg`؛ برای عکس واقعی `<id>.jpg` بگذار).
- مقاله‌ها: `data/posts.js`، شهرها: `lib/cities.js`.
- **نرخ ارز نمونه** است: `lib/currency.js`. قیمت‌ها در داده به دلار است و در نمایش تبدیل می‌شوند (انتخاب ارز در منوی بالا).
- محاسبه‌ی پرداخت (مالیات، امکانات اضافی، تخفیف): `lib/pricing.js`.

## پنل کاربری (`/account`)
از هدر («👤 پنل من»). بدون ورود، صفحه‌ی ورود (یا ورود سریع مهمان) نشان داده می‌شود.
- **نمای کلی:** آمار (رزروهای پیش‌رو، شب‌ها، خرج، ذخیره‌شده‌ها)، یادآوری‌ها (سفر نزدیک، مهلت لغو رایگان، پیام جدید، مقایسه)، «سفر بعدی» با شمارش معکوس، نمودار خرج ۶ ماه، شهرهای محبوب، پیشنهاد هتل.
- **رزروها:** پیش‌رو/گذشته/لغوشده، لغو رایگان تا ۴۸ ساعت قبل، کپی کد، رزرو دوباره.
- **علاقه‌مندی‌ها:** هتل‌های ذخیره‌شده + فهرست مقایسه. **پیام‌ها:** تاریخچه‌ی گفتگو با پشتیبان. **پروفایل:** ویرایش اطلاعات، واحد پول، ترجیحات، دانلود/پاک کردن اطلاعات.
- «سطح مسافر» فقط نمایشی است (بر اساس شب‌های رزروشده) و مزیت مالی ندارد.
- لینک «🛠 مدیریت» هم در هدر هست و فعلاً برای همه دیده می‌شود (فقط رمز `/admin` قفلش است).

## پنل مدیریت (`/admin`)
- ورود با رمز `sara-admin` (برای تغییر: `NEXT_PUBLIC_ADMIN_PASSWORD` در `.env.local`).
- **داشبورد:** درآمد، تعداد رزرو، میانگین ارزش رزرو، نرخ لغو، روند فروش (۷/۳۰/۹۰ روز یا همه)، پرفروش‌ترین هتل‌ها، درآمد هر شهر، مدت اقامت، روش پرداخت، توزیع ستاره و دسته‌بندی.
- **هتل‌ها:** جستجو و فیلتر، افزودن، ویرایش (اتاق‌ها، امکانات، عکس)، حذف تکی و گروهی، انتقال گروهی به یک دسته، بازیابی هتل‌های حذف‌شده.
- **دسته‌بندی‌ها:** افزودن، تغییر نام (ادغام) و حذف با انتقال هتل‌ها؛ دسته‌ها در صفحه‌ی هتل‌ها به‌صورت فیلتر دیده می‌شوند.
- **رزروها:** جستجو (کد، هتل، شهر، نام/تلفن مهمان)، **ابطال با کد پیگیری**، لغو/فعال‌سازی، حذف، خروجی CSV. **تنظیمات:** رزرو نمونه برای نمودارها، پشتیبان‌گیری JSON، بازگردانی.
- **گفتگوها:** صندوق پیام با فیلتر «بی‌پاسخ»، پاسخ‌های آماده، بستن/حذف گفتگو، زنگوله‌ی هدر با شمارنده و صدا، و کارت «گفتگوهای بی‌پاسخ» و «جستجوهای بی‌نتیجه» در داشبورد.
- **وبلاگ:** افزودن مقاله‌ی جدید (عنوان، دسته، شهر مرتبط، خلاصه، بخش‌های متن با تیتر و ترتیب دلخواه، عکس شاخص)، ویرایش مقاله‌های جدید و مقاله‌های اصلی، حذف و بازیابی، جستجو و فیلتر دسته. مقاله‌ی منتشرشده همان لحظه در `/blog`، صفحه‌ی اول و صفحه‌ی خودش دیده می‌شود و در پشتیبان JSON تنظیمات هم هست. ذخیره‌سازی در `lib/blog.js` (localStorage) است و `data/posts.js` دست‌نخورده می‌ماند.
- **چت روی سایت:** دکمه‌ی گفتگو (با زنگوله‌ی متحرک وقتی پاسخ جدید هست) پایین هر صفحه؛ دستیار هتل پیدا می‌کند، به سؤال‌های رایج جواب می‌دهد و اگر چیزی نبود می‌گوید «متأسفانه چیزی پیدا نشد» با ایموجی و همان عبارتی که کاربر نوشته. پیام‌ها برای ادمین هم ثبت می‌شود؛ تا ۱۰ دقیقه بعد از پاسخ ادمین، ربات ساکت می‌ماند.
- تغییرات هتل‌ها (`lib/store.js`) روی **همین مرورگر (localStorage)** ذخیره می‌شود؛ `data/hotels.js` دست‌نخورده می‌ماند. رمز پنل هم فقط یک قفل نمایشی است. برای استفاده‌ی واقعی باید دیتابیس و احراز هویت سمت سرور اضافه شود.

## دستیار سفر با هوش مصنوعی
فایل `.env.local` بساز (نمونه: `.env.example`) و کلید را بگذار:
```
ANTHROPIC_API_KEY=...
```
بدون کلید، یک تحلیل ساده‌ی محلی استفاده می‌شود. کلید فقط در سرور (`app/api/assistant/route.js`) خوانده می‌شود. خروجی مدل قبل از استفاده پاک‌سازی می‌شود. برای استفاده‌ی واقعی بهتر است محدودیت تعداد درخواست هم اضافه شود.

## نمایشی بودن
پرداخت فقط نمایشی است و اطلاعات کارت ذخیره نمی‌شود. رزروها، نظرها و پیام‌های تماس در مونگو ذخیره می‌شوند.

## نظرات کاربران (بک‌اند مونگو + تأیید مدیر)

- فقط `MONGODB_URI` را در `.env.local` بگذار (نمونه: `.env.example`)؛ کالکشن `reviews` خودکار ساخته می‌شود.
- کاربر از بخش «مسافرها چه می‌گویند» (صفحه‌ی اصلی) نظر می‌دهد → نظر با وضعیت `pending` ذخیره می‌شود و در سایت دیده **نمی‌شود**.
- ادمین در پنل مدیریت، تب «⭐ نظرات»: **تأیید** = در سایت نمایش داده می‌شود، **رد** = برای همیشه از دیتابیس پاک می‌شود.
- API: `app/api/reviews/route.js` (`POST` ثبت، `GET` نظرهای تأییدشده، `GET ?status=` + `PATCH` + `DELETE` فقط برای `role = ADMIN`).
- ضداسپم: فیلد مخفی (honeypot) + حداکثر ۳ نظر در ۱۰ دقیقه برای هر IP.

## تماس با ما: کپچا، پاسخ ادمین، پیگیری با کد

- **کپچا**: تصویر خودمیزبان (`/api/captcha`)، بدون سرویس خارجی و بدون کلید. هر تصویر فقط یک‌بار قابل استفاده است و بعد از ۵ دقیقه از مونگو پاک می‌شود. کنارش فیلد مخفی ضدربات و محدودیت ۵ پیام در ۱۰ دقیقه برای هر IP هم هست.
- **پنل ادمین → تب «📨 پیام‌ها»**: دیدن پیام‌ها، جواب دادن، بستن/بازکردن گفتگو. وضعیت‌ها: `new` ← `read` ← `replied` ← `done`.
- **کاربر**: بعد از ارسال، کد پیگیری (مثل `TK-7K2QX9`) می‌گیرد. در صفحه‌ی «ارتباط با ما» → تب «پیگیری پیام» کد را می‌زند، وضعیت و جواب را می‌بیند (هر ۲۰ ثانیه خودکار به‌روز می‌شود) و می‌تواند سؤال بعدی بپرسد. لینک مستقیم: `/contact?ticket=TK-XXXXXX`.
- API پیگیری: `POST /api/contact/track` (دیدن) و `PUT /api/contact/track` (سؤال بعدی). ایمیل کاربر هرگز نشان داده نمی‌شود. هر گفتگو حداکثر ۴۰ پیام و هر IP در ۱۰ دقیقه حداکثر ۲۰ جست‌وجو دارد.
- برای ساختن هش کپچا از `NEXTAUTH_SECRET` استفاده می‌شود (در `.env.local` تنظیمش کن).

## پنل کاربری ← تب «⚙️ تنظیمات»

- کاربر **نام**، **ایمیل** و **شماره‌ی تماس (اختیاری)** خودش را ویرایش می‌کند؛ همه در مونگو ذخیره می‌شود (`components/account/Settings.js` ← `PATCH /api/account`). لینک مستقیم: `/account#settings`.
- شماره‌ی تماس: فارسی/انگلیسی، با فاصله و خط تیره، `+98` و شماره‌ی خارجی (`+44…`) پذیرفته می‌شود و یک‌شکل ذخیره می‌شود (مثلاً `09121234567`). خالی‌گذاشتن = پاک‌کردن شماره.
- **تغییر ایمیل رمز عبور فعلی می‌خواهد** (ایمیل همان نام کاربری ورود است)، تکراری بودن ایمیل چک می‌شود و تلاش رمز غلط محدود است (۵ بار در ۱۰ دقیقه).
- فقط `name`، `email` و `phone` از این مسیر قابل تغییرند؛ نقش و رمز هرگز.
- نشست ورود حالا شناسه‌ی کاربر (`session.user.id`) را هم دارد، پس با عوض‌شدن ایمیل کاربر از حسابش بیرون نمی‌افتد. نشست‌هایی که قبل از این به‌روزرسانی ساخته شده‌اند id ندارند: اگر آن‌ها ایمیل را عوض کنند، یک بار خروج و ورود دوباره لازم است.

## رزروها (بک‌اند مونگو + پیگیری با کد + ابطال توسط ادمین)

رزروها دیگر در `localStorage` نیستند؛ در کالکشن `bookings` (مدل `models/Booking.js`) ذخیره می‌شوند و همه‌چیز از طریق API است.

**جریان کار**
1. کاربر در `/checkout` رزرو می‌کند → `POST /api/bookings` → سرور کد پیگیری (`SR-XXXXXX`) می‌سازد و به کاربر نشان می‌دهد. ورود به حساب لازم نیست؛ اگر وارد باشد رزرو به حسابش وصل می‌شود.
2. کاربر در `/track` کد را می‌زند و وضعیت را می‌بیند: **فعال**، **لغو شده** یا **باطل شده** (صفحه هر ۲۰ ثانیه خودش تازه می‌شود). ایمیل و تلفن مهمان هرگز در پیگیری نمایش داده نمی‌شود.
3. ادمین در `/admin` ← «رزروها» ← «ابطال رزرو با کد پیگیری» کد را وارد می‌کند، مشخصات رزرو را می‌بیند و «باطل کن» را می‌زند. باطل‌شدن **نهایی** است (ادمین هم نمی‌تواند فعالش کند) و کد دیگر معتبر نیست.

| متد و آدرس | دسترسی | کار |
|---|---|---|
| `POST /api/bookings` | عمومی | ثبت رزرو (محدودیت: ۱۰ رزرو در ۱۰ دقیقه برای هر IP) |
| `GET /api/bookings` | کاربر واردشده | رزروهای خودش |
| `GET /api/bookings?scope=all` | ادمین | همه‌ی رزروها با اطلاعات مهمان |
| `PATCH /api/bookings` | کاربر / ادمین | `{code, status}`؛ کاربر فقط لغو رزرو خودش تا ۴۸ ساعت قبل از ورود؛ ادمین لغو و فعال‌سازی |
| `DELETE /api/bookings?code=` | ادمین | حذف قطعی |
| `POST /api/bookings/track` | عمومی | `{code}` ← وضعیت رزرو (محدودیت: ۲۰ جست‌وجو در ۱۰ دقیقه) |
| `GET/POST /api/bookings/void` | ادمین | دیدن مشخصات و باطل‌کردن با کد (اتمیک؛ فقط رزرو فعال باطل می‌شود) |
| `POST/DELETE /api/bookings/admin` | ادمین | ساخت/حذف رزروهای نمونه، پاک‌کردن همه‌ی رزروها |

**نکته‌ها**
- سرور خودش کد پیگیری، تعداد شب‌ها و (برای هتل‌های `data/hotels.js`) نام هتل و حداقل مبلغ را بررسی می‌کند. هتل‌هایی که ادمین فقط روی مرورگر خودش اضافه کرده در سرور نیستند و مبلغ ارسالی‌شان بررسی نمی‌شود.
- رزروهای قدیمیِ `localStorage` به دیتابیس منتقل نمی‌شوند.
- ادمین بودن یعنی `role: "ADMIN"` در کالکشن `users` (مثل بقیه‌ی APIها).

## خبرنامه («پیشنهادهای ویژه را زودتر ببین»، بک‌اند مونگو + کپچا)

فرم عضویت پایین صفحه‌ی اول قبلاً نمایشی بود؛ حالا ایمیل‌ها در کالکشن `subscribers` (مدل `models/Subscriber.js`) ذخیره می‌شوند.

- **عضویت:** `POST /api/newsletter` با کپچای تصویری (همان `/api/captcha`، یک‌بارمصرف) + فیلد مخفی ضد ربات + محدودیت ۵ درخواست در ۱۰ دقیقه برای هر IP. تصویر کپچا فقط وقتی کاربر روی کادر ایمیل کلیک کرد ساخته می‌شود، پس بازدید معمولی صفحه چیزی در دیتابیس نمی‌نویسد.
- **ایمیل تکراری:** جواب «ثبت شد» است (چه تازه چه تکراری) تا کسی نتواند بفهمد یک ایمیل عضو بوده یا نه؛ اگر قبلاً لغو کرده بود دوباره فعال می‌شود.
- **لغو عضویت:** هر مشترک یک `token` اختصاصی دارد. لینک `/unsubscribe?token=...` را داخل ایمیل‌های خبرنامه بگذار.
- **ادمین:** تب «📬 خبرنامه» در `/admin`: جستجو، فیلتر فعال/لغوشده، حذف، خروجی CSV مشترک‌های فعال (`GET/DELETE /api/newsletter`، فقط `role: "ADMIN"`).
- **ارسال ایمیل:** هنوز پیاده نشده؛ فعلاً فقط جمع‌آوری مشترک‌هاست.
